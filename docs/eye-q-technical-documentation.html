Eye-Q

An open-vocabulary vision–language retrofit appliance that turns conventional IP cameras into cameras you can ask questions of, in plain English, with no model training and no cloud.

§0Abstract

Conventional IP cameras detect motion; they cannot answer questions. Retrofitting semantic alerting onto them normally means training a bespoke detector for every condition — a hard-hat model, a spill model, a blocked-exit model — putting each new question behind its own labelling cycle. Eye-Q removes that cycle: an operator types the condition as a sentence, “Is this person bending over?”, and a vision–language model answers it per subject, per frame, with no training and nothing leaving the device.

The problem this creates is arithmetic. A VLM able to answer an arbitrary question about an image costs seconds per query on edge CPUs, while a camera delivers thirty frames a second. Eye-Q resolves the mismatch with a two-stage cascade that arbitrages three orders of magnitude of latency: YOLOv8n runs continuously at 2–4 ms per frame and does nothing but decide when reasoning is worth paying for; Moondream2 wakes only for the subjects that survive that gate. Between them sits a zero-copy shared-memory ring whose readers are lock-free and stale-tolerant, so the slow stage can lag seconds behind live without the fast stage ever blocking.

The substance lies after the gate. Stage 1 assigns every detection a stable identity, so a frame of five workers yields five judgements rather than one — which multiplies inference demand by the size of the crowd and must therefore be paid for. Stage 2 pays with four ordered layers of load control — coalescing superseded triggers, memoising each subject’s verdict, prioritising subjects never yet seen, truncating the batch — all governed by one formula an operator can reason about: duty = subjects × inference_s ÷ ttl. Correctness measures carry equal weight: each crop is dimmed outside the subject’s own box so a neighbour cannot flip its verdict, and every crop is taken before the first slow inference, so inference latency can never outlive the buffer it depends on.

§1System architecture

1.1  One process, four unequal threads

Everything runs in one process because of the ring buffer: a shared-memory frame store removes copies only if consumers reach it without serialising, and keeping both stages as threads in the owning process makes that free. The segments are nonetheless named POSIX objects, so the multi-process seam exists when wanted. The threads are deliberately unequal — capture writes into a ring that overwrites rather than fills, Stage 1 is paced independently of capture because otherwise it starves the stage it exists to feed, and Stage 2 is kept entirely off the frame path.

1.2  Two transport planes, single ownership

Detections travel on :5557, verdicts return on :5558. The split is not tidiness — ZeroMQ sockets are not thread-safe, so each publisher owns its socket in the thread that created it, and Stage 2 builds both of its own inside its worker loop. Sends are non-blocking behind a high-water mark: a slow consumer drops messages rather than stalling a producer. Ownership is likewise singular — the FastAPI lifespan builds every component in dependency order and tears it down in reverse, the fix for a defect where split ownership let the lifespan overwrite already-wired components and silently sever rule delivery to the VLM.

§2End-to-end workflow and data flow

Two invariants govern this path, each found by fixing the failure its absence causes. Crop before inference: inference takes seconds and the ring holds seconds, so fetching a frame just before each query leaves the second subject in a group with its frame already overwritten — invisible in a one-subject scene, total in a crowded one. Coalesce by subject, not label: keeping only the newest trigger per class discards four of five workers as “superseded” when they are different people. Rules flow the other way: sync_rules() hands Stage 1 the coarsest filter satisfying every rule.

§3The AI/ML layer

Stage 1 is the motion filter, not the classifier: YOLOv8n can only ever say “person” about a warehouse worker, and every question worth asking is asked by Stage 2 in English. Identity must be resolved before the gate can work, and is — a greedy IoU tracker matches boxes within a label across frames, chosen over ByteTrack because Ultralytics resolves its lap dependency at import time by attempting a runtime pip install, a hard failure offline. A swap under occlusion costs one redundant inference, never a missed alert.

§4Innovation — what is genuinely hard here

Two carry disproportionate weight. Four-layer load control with a published formula is what makes per-subject judging affordable rather than merely correct, and the status endpoint exposes instances_judged, instances_memoised and instances_shed so the arithmetic can be checked against reality. Focused crops are the subtlest: the padding that lets a VLM answer relational questions at all is the same padding that drags in the neighbours.
